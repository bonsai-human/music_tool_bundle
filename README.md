# music tool bundle

ちょっとした音楽系ツールをまとめた、自分用のウェブアプリ。
ビルド不要の静的サイトで、GitHub Pages にそのまま置いて使う。

**公開URL**: `https://bonsai-human.github.io/music_tool_bundle/`

## 収録ツール

| ツール | 状態 | 内容 |
| --- | --- | --- |
| [音叉](tools/tuning-fork/) | 公開中 | A1〜C7 の基準音を鳴らす電子音叉。A4 較正 415〜466Hz、波形 4 種、高調波量、音圧レベル。 |
| [メトロノーム](tools/metronome/) | 公開中 | 拍子12種＋任意拍子、拍ごとのアクセント、リズムパターン、音色5種、練習プログラム。 |
| [コード判定](tools/chord-finder/) | 公開中 | 鍵盤で選んだ音からコード名を判定。複数の読み方を候補として並べ、ベース音で絞り込める。 |
| [チューナー](tools/tuner/) | 公開中 | マイクから音高を検出しセント単位で表示。楽器プリセット、音高の推移グラフ、音域の記録。 |

## 設計方針

iOS アプリを 1 本ずつ入れる代わりに、**1 つのサイトに小さなツールを足していく**構成にしている。

- **ビルドなし** — 素の HTML / CSS / ES モジュール。`git push` した内容がそのまま本番。
  ツールチェーンの更新に追われず、数年後でも直せる。
- **依存ゼロ** — 外部 CDN もフォントも読まない。オフラインで完全に動く。
- **相対パスのみ** — GitHub Pages のサブディレクトリ配信（`/music_tool_bundle/`）でも
  ローカルの `python -m http.server` でもそのまま動く。ルート絶対パス (`/shared/...`) は使わない。
- **共有基盤 + 独立したツール** — 音律の計算・AudioContext・設定保存といった
  「どのツールでも要るもの」だけを `shared/` に置き、ツール同士は依存させない。
  1 つのツールが壊れても他は動く。
- **PWA** — Service Worker で全ファイルを事前キャッシュ。ホーム画面に追加すれば
  電波の無いスタジオや練習室でも起動する。

## 音叉ツールについて

元の iOS アプリの機能をそのまま移植したうえで、ウェブ向けに少し足している。

- **音符** — A1〜C7 を半音単位で選択。スライダー上下に A / C の目盛りを表示。
- **A4 較正** — 415〜466Hz を 0.5Hz 刻みで。周波数は `a4 × 2^((midi−69)/12)`。
- **音圧レベル** — 二乗カーブでゲインへ変換（聴感上リニアになる）。
- **高調波** — 0% で純正弦波、100% で選んだ波形そのもの。
  基本波形の理想倍音列に指数状の傾き `exp(−k(n−1))` を掛けて連続的に補間している
  （`shared/js/wave.js`）。正弦波選択時は倍音が無いので無効化される。
- **波形** — 正弦波 / 三角波 / のこぎり波 / 矩形波。すべて `PeriodicWave` で生成し、
  ナイキスト周波数を超える倍音は落としてエイリアシングを防ぐ。
- 追加した点: 設定の自動保存、発音中の画面スリープ抑止、タブを離れると自動停止、
  発音開始・停止のフェード（プチノイズ防止）、キーボード操作、オフライン動作。

### 参考アプリとの関係

機能は市販の iOS 音叉アプリを参考にしているが、画面は流用していない。
初版が見た目まで寄りすぎていたため、以下を変更した。

- 「音名｜音叉｜周波数」を左右対称に並べる構成をやめ、音叉を左・読み取り値を右に積む構成へ
- アクセント色を緑から青緑へ（メトロノームの琥珀とも区別する）
- 波形アイコンの4色（青・黄・赤・緑）をやめ、選択中だけアクセント色にする単色配色へ
- 上部中央に緑で置いていた較正値を、周波数の下の小さなピルへ移動

## メトロノームツールについて

### テンポが揺れないしくみ

`setInterval` で直接音を鳴らすと、タイマーの揺れがそのままリズムの揺れになる。
そこで `shared/js/scheduler.js` が、粗いタイマー（25ms）で定期的に起きて
**少し先（120ms）の音を AudioContext の正確な時刻軸へ予約する**方式をとっている。
発音時刻はオーディオスレッドが保証するので、UI が重くなってもテンポは狂わない。
実測でも予約時刻の誤差は 0ms（浮動小数の加算のみ）。

### 1小節のモデル

```
1小節 = beats 拍、1拍 = subdivision スロット
各スロットの鳴らし方は slots 文字列で決まる:
  'B' … その拍のアクセント設定（強 / 弱 / 休）に従う
  's' … 分割の音
  '-' … 鳴らさない
```

この 1 つのモデルで、基本・8分・3連・16分・スウィング（`B-s`）・付点（`B--s`）を
すべて表現している。6/8・9/8・12/8 を選ぶと 3 拍ごとに強拍が自動で入る。

### 音色

音源ファイルは持たず、5種すべて Web Audio のノードで合成している（依存ゼロ・
オフライン動作のため）。音色ごとに素のピークが 0.26〜0.95 と 4 倍近く開くので、
オフラインレンダリングで実測した値から逆算した係数で音量をならし、
分割が細かいときの打点の重なりに備えて軽いリミッタを挟んでいる。

### 練習プログラム

指定した小節数 × 繰り返し回数を弾くごとにテンポを上げ、目標に達したら停止する。
開始前のカウント、テンポが上がるときのベルを個別に切り替えられる。

### 参考アプリとの関係

機能面は市販の iOS メトロノームアプリ 2 本を参考にしているが、画面は流用していない。
1小節を円に見立てたリング型ダイヤルという見立ては独自のもので、
横並びのドット列・振り子ロッドといった参考アプリの表現は使っていない。
Bossa / Latin のようなプリセットは、2小節のクラーベを1小節に畳むと嘘になるため入れていない。

## コード判定ツールについて

### なぜ鍵盤が1オクターブなのか

参考にしたアプリは横画面で2オクターブの鍵盤を持つが、そのまま縦画面に載せると
白鍵が 20px 前後になって指で押せない。

コード名は**オクターブの積み方では変わらない**（C-E-G をどう並べても C）。
決まるのは「どの音名が含まれるか」と「ベースが何か」だけなので、鍵盤は
1オクターブ（ピッチクラス）に絞り、転回形・分数コードはベース音の指定で表す。
これで 320px 幅でも白鍵が 39px、390px なら 49px 確保できる。

### 判定のしくみ（`shared/js/chords.js`）

12通りのルートそれぞれについて、選択された音をルートからの半音数に直し、
40種類のコード辞書と集合として突き合わせる。完全一致が無い場合だけ、
5度を省略した形として解釈できるものを候補にする（「om5」と表示）。

同じ音の集合に複数の名前がつくのは正常な状態（C-E-G-A は Am7 でも C6 でもある）。
ピッチクラスには上下の情報が無いので、ベース音の指定が無いときは位置で優劣を
つけず、コード種類のありふれ具合だけで並べ、候補はすべて残して選べるようにしている。
ベース音を指定すると、それをルートとする解釈を強く優先する。

### 綴りは度数で決まる

異名同音はルートの調号ではなく**度数**で決める。C の♭3は必ず E♭（D♯ ではない）、
♯9 は D♯（E♭ ではない）。ルート基準で決めると `Cm7♭5/D♯` のような誤った表記が出る。

## チューナーツールについて

### 音高検出の方式（`shared/js/pitch.js`）

MPM（McLeod Pitch Method）系。FFT 経由で自己相関を求め、NSDF（正規化二乗差関数）に
直してから山を選び、放物線で補間する。

- **なぜ素朴な自己相関でないか**: 最大値をそのまま採るとオクターブを間違える。
  NSDF の「最大値の0.9倍を超える最初の山」を選ぶとこれを避けられる。
- **なぜ YIN でないか**: 精度は良いが `O(窓長 × 最大ラグ)`。低音まで見るために
  窓を4096にすると1フレーム840万回の演算になり、スマホでは間に合わない。
  FFT 経由なら `O(N log N)` で同じ結果が出る（実測 1.1ms/フレーム）。
- **倍数での測り直し**: 高音は1周期のサンプル数が少なく（1100Hz で43サンプル）、
  頂点補間だけでは分解能が足りない。NSDF は周期の整数倍にも山を持つので、
  窓に収まる倍数の山で測り直して相対分解能を上げている。
  これで矩形波の最大誤差が 1.12¢ → 0.14¢ に下がった。

検証は `tests/pitch.test.mjs`（DOM 非依存なので node だけで走る）。

| 項目 | 結果 |
| --- | --- |
| 正弦波 E2〜D6 全47半音 | 最大 0.002¢ |
| のこぎり波 同上 | 最大 0.087¢ |
| 矩形波 同上 | 最大 0.135¢ |
| B0 (30.87Hz) | 検出可、誤差 0.00¢ |
| 基音が弱い波形37音 | オクターブ誤り 0件 |
| ノイズ混入（S/N 約18dB） | 最大 0.04¢ |
| 1フレームの解析時間 | 1.10ms |

### iOS で気をつけること

`getUserMedia` の制約で `echoCancellation` / `noiseSuppression` / `autoGainControl` を
**明示的に false にする**。既定で有効になり、音程が歪んで正しく測れない。

### 画面

`getFloatTimeDomainData` で 4096 サンプル取り、30回/秒で解析する。表示は直近5フレームの
中央値をとって数字の暴れを抑えている。メーターのラベル・目盛り・針は
`left: calc(50% + --at * 46%)` という同じ式で配置していて、読み違いが起きないようにしてある。

## 開発

```sh
python3 -m http.server 8000
# → http://localhost:8000/
```

Service Worker はローカルでも有効なので、キャッシュが残って更新が反映されない場合は
DevTools の Application → Service Workers → Update on reload を使う。

コード判定と音高検出のロジックは DOM に依存しないので、Node だけで検証できる。

```sh
node tests/chords.test.mjs   # コード判定 36件
node tests/pitch.test.mjs    # FFT と音高検出の精度 12件
```

### ツールを追加する手順

1. `tools/<tool-id>/` に `index.html` / `<tool-id>.css` / `<tool-id>.js` を作る。
   共通部分は `shared/css/base.css` と `shared/js/*` を相対パスで読む。
2. `shared/js/registry.js` にエントリを 1 つ追加する（トップページのカードは自動生成）。
3. `sw.js` の `PRECACHE` に新しいファイルを足し、`CACHE_VERSION` を上げる。

## デプロイ

`.github/workflows/pages.yml` がデフォルトブランチへの push で自動デプロイする。
初回のみ GitHub の **Settings → Pages → Source** を **GitHub Actions** に設定する必要がある。
